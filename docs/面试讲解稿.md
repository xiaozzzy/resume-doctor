# 项目面试讲解稿

## 30 秒版本

简历医生是我做的 AI 求职辅助工具。它把“看简历、改简历、排版、面试准备”从分散动作串成一个流程：用户输入简历和 JD 后得到结构化诊断，接着生成只基于真实经历的改写稿，编辑后可以导出一页纸 PDF，并用同一份材料生成模拟面试题。我最关注的不是让模型写得很像，而是让建议可追溯、改写不编造、用户能继续核对和编辑。

## 我如何定义问题

最初的假设是，求职者缺的不是一篇通用教程，而是面对具体 JD 时快速判断差距并改出一版可投递材料的能力。因此 MVP 没有从“做一个模板库”开始，而是先验证“输入简历 + JD 后，用户是否愿意按建议继续改写和导出”。

## 关键取舍

| 取舍 | 选择 | 原因 |
| --- | --- | --- |
| 评分展示 | 五维评分 + 原文问题清单 | 单一总分没有行动指引，原文引用让建议可核对 |
| 改写策略 | 事实约束 + `[X]` 占位 | 宁可让用户补数据，也不把推测写成业绩 |
| 输出形态 | 可编辑 Markdown + 模板 PDF | 用户需要可控的投递材料，不是不可修改的黑盒结果 |
| 输入门槛 | 粘贴、PDF、图片三种入口 | 适配不同准备程度；文本 PDF 优先浏览器端解析 |
| 登录时点 | 仅真实 AI 请求前要求登录 | 先让用户看到演示价值，避免一进来就被注册打断 |

## 技术实现

前端是原生 HTML、CSS 和 JavaScript，部署在 Vercel。Serverless 接口分别承载诊断、改写、面试、图片转录、验证码与统计。模型层使用 OpenAI 兼容接口：诊断和面试尽量要求 JSON 输出，服务端仍进行解析和基本字段校验。API Key 只在环境变量中使用。

## 我会如何验证

我不会虚构“转化率提升”等结果。下一步会用漏斗验证：输入后完成诊断的比例、报告后进入改写的比例、生成改写后导出的比例，以及用户是否核对并采用了建议。更关键的定性问题是：用户能否指出某条建议对应自己的哪句话，能否发现 `[X]` 并补成真实数据。

## 已知限制与下一步

当前 OCR 依赖模型服务，扫描件效果受图像质量影响；模型建议也可能需要用户判断。KV 未配置时的降级逻辑适合演示，不是生产级权限控制。若继续产品化，我会先补严格的失败拒绝、服务端限流和匿名漏斗，再考虑多轮追问和长期简历管理。
