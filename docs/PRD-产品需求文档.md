# 简历医生(Resume Doctor)产品需求文档

> 版本 v1.0 · 作者:[你的名字] · 最后更新:2026-07

## 1. 背景与问题定义

**用户痛点**:应届生和转行求职者投递简历的回复率普遍低于 10%,但大多数人并不知道自己的简历"病"在哪里——是关键词与 JD 不匹配被机器筛掉了,还是经历描述缺乏量化结果打动不了 HR。市面上的简历修改服务价格在 200–800 元/次,且交付周期 1–3 天,无法支撑"一天投 20 个岗位、每个岗位定制简历"的真实求职节奏。

**机会判断**:大语言模型具备理解 JD 语义、评估文本匹配度、生成改写建议的能力,可以把"资深 HR 看简历"的经验产品化,做到**秒级、免费、可反复使用**。

## 2. 目标用户

| 用户画像 | 核心诉求 | 使用场景 |
|---------|---------|---------|
| 应届生 | 不知道简历好不好,投了没回音 | 秋招/春招前集中优化 |
| 转行求职者 | 不知道如何把过往经历"翻译"成目标岗位的语言 | 针对每个 JD 定制简历 |
| 有经验跳槽者 | 想快速判断自己与某个 JD 的匹配度,值不值得投 | 投递前 30 秒快速自检 |

## 3. 核心功能(MVP 范围)

**一句话描述**:粘贴简历 + 粘贴目标 JD → 30 秒内得到一份"诊断报告"。

### 3.1 输入
- 简历文本(粘贴)
- 目标岗位 JD(粘贴,可选——不填则做通用体检)

### 3.2 输出:诊断报告
1. **总体匹配度评分**(0–100)+ 一句话总评
2. **五维评分拆解**(雷达式呈现):
   - 岗位匹配度:关键词与技能是否覆盖 JD 要求
   - 量化程度:经历是否有数字化结果(STAR 中的 R)
   - 表达质量:是否使用动作动词、避免空话套话
   - 结构完整度:模块是否齐全、顺序是否合理
   - 关键词覆盖:硬技能词是否命中(应对 ATS 机器筛选)
3. **问题清单**:按严重程度(高/中/低)列出具体问题,每条附原文引用
4. **改写示范**:挑 2–3 条最有问题的经历描述,给出"原文 → 改写后"对照
5. **缺失关键词提示**:JD 中出现但简历中未覆盖的技能词

### 3.3 明确不做(v1 不做的事及原因)
- ❌ PDF 解析:粘贴文本已覆盖核心流程,解析格式复杂且易错,v2 再做
- ❌ 用户账号体系:MVP 验证核心价值,不设注册门槛
- ❌ 简历模板/生成:市面已有成熟方案,不是差异化点

## 4. AI 方案设计(PM 视角)

### 4.1 模型选型
选用 DeepSeek-V3(deepseek-chat):中文理解强、成本低(单次分析约 ¥0.005)、API 兼容 OpenAI 格式便于日后切换模型。

### 4.2 Prompt 策略
- **角色设定**:10 年经验的资深 HR + 猎头双重视角
- **结构化输出**:强制 JSON Schema 输出,保证前端渲染稳定
- **评分锚定**:prompt 中给出各分数段的判定标准(如 80+ = 可直接投递),抑制模型"分数虚高"的倾向
- **引用原文**:要求每个问题必须引用简历原文,防止模型泛泛而谈(降低幻觉)

### 4.3 已知风险与对策
| 风险 | 对策 |
|------|------|
| 模型评分不稳定(同一简历两次分数差异大) | 温度设为 0.3;评分标准写入 prompt 锚定 |
| 用户粘贴超长文本导致成本/延迟上升 | 前端限制输入 8000 字符 |
| 隐私顾虑(简历含个人信息) | 不存储任何用户数据,前端明示;建议用户脱敏 |
| 无 Key 时无法体验 | 内置演示模式,一键查看样例报告 |

## 5. 成功指标(如何验证)
- **北极星指标**:完成一次完整诊断的用户数
- 辅助指标:诊断完成率(点击分析→看到报告)、单用户重复使用次数(定制多份简历的信号)
- MVP 验证方式:发放给 20 位正在求职的同学使用,回收"是否按建议修改了简历"与"是否愿意推荐给朋友"两个问题的反馈

## 6. 版本规划
- **v1.0(本版)**:文本粘贴 → 诊断报告,演示模式
- v1.1:PDF 上传解析;报告导出为图片便于分享(自带传播属性)
- v2.0:按 JD 一键生成定制版简历;多轮追问("这段实习该怎么写?")
